## O que copiar

- **`crates/sixng-core/src/scan.rs`** — índice de container com diretório cifrado por carving de streams zlib, agrupamento por três sinais e, o ponto não óbvio, extensão do grupo pelo **page-map pointer interno** (`sys_need_of`, `pm >> 28 == 5` → `(pm & 0x0FFF_FFFF) + 8`) com `group_tests` fixando a fronteira (`6b68f75`, `b7fbe3a`, `d7e9bdc`).
- **`crates/sixng-core/src/bc6h.rs` + os `*pack.rs`/`*pack_tables.rs`** — decoders BCPack por especificação, com a regra como restrição (no-wrap, three-colour sem índice 3, p-bit) e o padrão de aceitar slot só se ele se sustenta contra o mip vizinho (`2979c57`, `063d35e`, `783eaa4`). Copiar o código e o método; **não** copiar as tabelas sem o conjunto de validação.
- **`crates/sixng-gui/src/glb.rs::uv0_tangents`** — frame tangente reconstruído do UV de amostragem, 46 linhas, sem dependência (`3bfa416`), e a mesma rotina deve ir para o exportador, que é onde falta (F-08).
- **`crates/sixng-core/src/meta7a.rs`** — desambiguação por **ordem** (pool antes de ponteiro real) justificada por censo de todos os casos ambíguos (`38de2e5`): o padrão vale para qualquer formato RAGE auto-descritivo.
- **`crates/sixng-core/src/vehcolour.rs`** — `EXPORT_VERSION`/`FORMAT` como contrato versionado do artefato exportado, com a legenda de cada número no próprio código (21 `_COLOR1`, 22 `part_patches`, 23 `sliding_doors`, 24 slot de pneu não aplicado) e `INDEX_VERSION` em `lib.rs` (`593c106`, `5f7a635`).
- **`crates/sixng-core/src/bc1pack.rs`** — a decisão de **não aplicar** um dado decodificado cujo efeito não se conhece (`if ch == TYRE_COLOUR_CHANNEL { continue; }`, `5f7a635`): vale como padrão para toda a camada de materiais.
- **`crates/sixng-cli/src/main.rs`** — `--bench` com checksums (`9d08383`), `--then` para reproduzir troca de modelo (`3d510aa`), `--force` como escape de cache (`6e23570`) e contrato de saída JSON/JSONL/GLB estável.
- **`crates/sixng-core/examples/`** — 54 sondas de pesquisa versionadas com uma linha de uso no cabeçalho (`ptrcensus.rs` classifica todo membro ponteiro/array/map de todo objeto `7a` como pool, ponteiro real ou ambíguo; `regroup.rs` reproduz o split de recurso; `propbad.rs`, `mips.rs`, `hashgrep.rs`, `brute.rs`): é o que torna um censo auditável em vez de uma afirmação. Levar o padrão inteiro, não os arquivos.
- **O README como especificação viva** — cada linha de estado com data e número medido ("since 2026-11-21", "81 % → 86 %", "before, 22 resources were split in two"), e o que não se sabe admitido na mesma frase. É o formato que faz uma análise de engenharia reversa sobreviver ao autor.
- **`origin/claude/rpf9-toc`** (`gamecipher.rs`, `rpf9toc.rs`, `5433b45`) — mapear o executável do jogo como imagem, prover só as rotinas C importadas, trap em todo outro import e chamar `setkey`/`decrypt` do próprio jogo, com `BUILD_STAMP`/`IMAGE_SIZE` validando a build. Copiar com detecção de build por assinatura e fallback para carving.

## O que não copiar

- **Deixar a capacidade pronta fora do produto.** 1.294 linhas que resolvem a limitação central do projeto, 2 commits à frente e 0 atrás de `master`, paradas há um dia, com o README afirmando que a capacidade não existe (F-01, P-01). Merge de branch atualizada é barato; dívida de integração de um dia não é.
- **O fluxo de 191 branches e 332 commits duplicados** (P-03). Um squash por PR com o corpo preservado resolve os dois problemas de uma vez: `git log` de `master` passaria a conter a medição (P-02) e o histórico deixaria de mostrar a mesma mudança duas vezes.
- **Ajustar tabela por métrica sem versionar o ajuste.** `bc6pack_tables.rs` com 22 revisões e nenhum script/holdout no repositório significa que ninguém, nem o autor, reproduz o estado atual (P-04). Se a tabela é um ajuste, o conjunto de validação e o ajustador têm de ir junto — e a métrica tem de ser por artefato, não por slot (P-05).
- **Três mecanismos de invalidação de cache mais uma flag** (`INDEX_VERSION`, `EXPORT_VERSION`, `FORMAT`, `--force`). O buraco entre eles produziu F-10; um `CACHE_VERSION` único cobrindo todos os artefatos derivados, com `--force` só como escape, é mais barato que a soma das partes.
- **O renderer Metal 4 e a GUI** (`render3d_metal4.rs`; `d2dbb28`, `d328a4b`, `3e01b0f`, `560901b`, `4bec3df`): código de plataforma macOS que não serve a um pipeline de assets e que arrasta o fork pessoal de `metal-rust` (P-09).
- **Quatro abordagens sucessivas para a mesma pergunta** (cor de peça: `3b50a33` → `ed9ecf4` → `4c2fe2a` → `1f4318f`, com `EXPORT_VERSION` subindo a cada uma): o custo não é o retrabalho, é que cada versão intermediária gerou exports que precisaram ser refeitos. Ler a paleta de material primeiro teria evitado três delas.
- **Célula de README de 9.000 caracteres** (P-08) como única especificação de um subsistema. O conteúdo é excelente; o formato impede revisão por diff e garante que a próxima correção apague contexto em vez de ajustá-lo.
- **Pendências declaradas só em corpo de commit** (P-07) — inclusive uma corrida de carregamento admitida e não tratada (F-09, freios).

## Veredito

SixNG é um projeto de cinco dias e 303 commits cujas melhores correções são todas da mesma espécie: o código estava coerente com uma suposição errada sobre o formato, e o conserto substituiu a suposição pela fonte de verdade — o offset em bytes do descritor (`2cf005b`), o page-map pointer do próprio recurso (`b7fbe3a`), o header do blob de malha (`e7aae6b`), o UV com que o mapa é amostrado (`3bfa416`), o layout do store em vez do campo do descritor (`8fa1281`), o censo de todos os casos ambíguos em vez de uma ordem preferida (`38de2e5`). Isso é engenharia de verdade, e vem acompanhada de números antes/depois em unidade verificável, o que permitiu ao próprio autor flagrar as duas regressões de calibração (`9ce31d3`, `18bc31c`) e corrigi-las com o mesmo rigor — inclusive revertendo seis slots que ele mesmo havia escolhido. O que impede a nota de ser alta é o que o projeto fez com o resultado: a maior peça de código do repositório, 1.294 linhas que leem o TOC do RPF9 chamando as rotinas de cifra do próprio jogo, está pronta em uma branch que já contém todo o `master` e nunca foi mergeada, enquanto o README de `master` afirma que a capacidade não existe. Somam-se 332 commits que só vivem em 189 branches (vários duplicados), um squash que descarta a medição que justifica a mudança, um pipeline de tabelas cujo estado não é reproduzível a partir do código e um autor responsável por 92 % do histórico. O passivo funcional é baixo — os defeitos de impacto estão corrigidos —, mas o passivo de integração e de processo é o que decide se este projeto serve como base: vale copiar o núcleo, os decoders e o método de medir; não vale copiar o modo de trabalhar.
